# Known-good physics for 05_Loop_1A_50Hz, asserted by ./verify_loop.py.
#
# WHAT THIS CASE ADDS THAT NOTHING ELSE IN THE SUITE HAS. Cases 01-04 are all a
# straight rod: SIMPLY CONNECTED, and the tree-cotree gauge has nothing hard to
# do on one. A closed ring is MULTIPLY CONNECTED. The current circulates with no
# terminal anywhere on the outer boundary, the cotree has to span the loop, and
# the only way to drive it is to CUT it. A gauge that wrongly killed the loop
# would show up here and in no other case.
#
# It is verified by ./verify_loop.py, not ../verify.py: the rod verifier finds
# the drive by differencing Phi between two end caps, and a ring has none.
#
#   key                value        tol      what sets the tolerance
# ---------------------------------------------------------------------------
input                  loop_50hz.aphi

# geometry. A 20-gon tube cross-section revolved about z, in a 90 mm x 90 mm
# cylinder of air -- see the L block below for why the domain is that large.
loop_radius_mm         6.5
wire_radius_mm         0.8
ngon                   20
sigma                  5.8e7
frequency              50.0

# THE PORT'S OWN PROMISE: inject 1 A across the cut and 1 A must cross it.
drive_current          1.0          1.0e-3

# AND THE CHECK NO OTHER CASE CAN MAKE: the same 1 A must cross theta = pi/2,
# a plane with NOTHING prescribed on it. Measured 1.000176 against the cut's
# 1.000503 -- the current really does circulate the whole way round. This is
# the multiply-connected test, and it is the reason the case exists.
circulation_tol        1.0e-3

# R AGAINST THE EXACT VALUE FOR THIS SHAPE, computed in the verifier straight
# off the mesh. Note it is NOT 2 pi R/(sigma A): current flows azimuthally, so
# the path length is 2 pi rho and varies across the section, and the
# conductance is sigma * integral(dA / 2 pi rho) -- the current crowds toward
# the inner radius. Ignoring that is a 0.44 % error, an order above the
# solver's own. Measured 3.542415e-04 against 3.546953e-04 exact, -0.128 %.
# Derived and compared in full in section 5.1/5.3 of LoopValidation; the numbers
# come from ./analytic_comparison.py.
R_rel_tol              2.0e-3

# ---------------------------------------------------------------------------
# L IS NOW A VALIDATION, NOT ONLY A REGRESSION GUARD -- AND THAT TOOK MOVING
# THE OUTER BOUNDARY, WHICH TWO EARLIER TESTS HERE WRONGLY RULED OUT.
#
# Measured 19.7854 nH against the published closed form for a circular loop of
# round wire, L = mu0 R [ln(8R/a) - 2 + 1/4] = 19.8027 nH: -0.09 %. For scale,
# using the 20-gon's equal-area radius a_eq = 0.79343 mm instead of its
# circumradius gives 19.8704 nH, so WHICH RADIUS you call `a` is itself worth
# 0.34 % and no comparison here means anything below that.
#
# IT WAS -2.15 %, AND ALL OF THAT WAS THE AIR DOMAIN. `outer = flux_tangential`
# sets n.B = 0 on the wall, which confines the return flux and acts like a
# flux-EXCLUDING shell -- an image loop of opposing current. Less flux links the
# ring, so L reads low; flux is pushed out of the middle, so B on the axis reads
# low; the excluded flux crowds along the wall, so B out there reads high. At
# the 30 mm this case used to ship, the wall was 2.3 loop radii out.
#
# Moving it to 90 mm (loop.geo; loop_small.geo keeps the 30 mm as the control,
# graded so element size ON THE LOOP AXIS matches to within 10 %, which is what
# makes it a control) fixes three independent observables at once:
#
#     L                                   -2.15 %  ->  -0.09 %
#     B on the loop axis, at the centre   -2.51 %  ->  -0.37 %
#     B in the air, 12-20 wire radii out +24.69 %  ->  +0.73 %
#
# AND IT IS CHEAPER, which is why there was never a reason not to: Threshold
# grades linearly in distance, so scaling lc_far and d_far with the domain
# reproduces the old grading where the fields are while putting far fewer
# elements in the empty mid-field.
#
#                        90 mm       30 mm
#     tets             217,719     223,879
#     unknowns         509,598     524,050
#     MUMPS fill       674.1 M     724.0 M
#
# TWO RETRACTIONS, AND THEY ARE THE SAME MISTAKE TWICE. This file used to say
# (a) "refining the tube moved L the wrong way, so resolution is NOT the cause"
# and (b) "the domain is ruled out -- doubling it to 60 mm moved L by +0.2 %".
# Test (a) refined lc_ring globally while half the ring was still being meshed
# coarse by the +Pi/-Pi sweep bug below, so it was measuring the bug. Test (b)
# used a mesh that still carried that same bug AND coarsened the far field so
# much that elements near the loop grew from 4 mm to 8.8 mm -- two variables,
# neither controlled. Both were negative results from an experiment that moved
# more than one thing, and between them they pointed away from the real cause
# for months. That is the lesson worth keeping from this case.
#
# THE HALF THAT WAS A MESH BUG, for the record. The ring used to be revolved as
# one +Pi sweep and one -Pi sweep. Both halves came out with the right volume --
# 40.386 against 40.307 mm3 -- but the negative-angle half got 4557 tets against
# 11621, elements 23 % larger and two and a half times fewer. Half the conductor
# was quietly meshed coarse. Chaining two POSITIVE sweeps gives a count ratio of
# 0.988, and on the 30 mm domain of the day L moved 19.038 -> 19.377.
#
# EXTRACTING L HERE IS ILL-CONDITIONED, worth knowing before reading any of it.
# omega*L/R is 0.017: the reactance is 1.7 % of the resistance, so Im(Z) is a
# small difference on a large product. Dividing by the MEASURED current instead
# of the imposed 1 A lets that current's own 0.02 % imaginary part into the
# answer and moves L by 1.3 %, fifty times its own size. The verifier divides by
# the imposed current and says why.
#
# The tolerance below is 0.25 % of the value, which is a regression guard; the
# agreement with theory is the 0.09 % above, and section 5.6 of LoopValidation
# carries the comparison.
# MEASURED GAUGE-SAFE, AND ONLY BECAUSE IT IS AN INTEGRAL. L comes from
# Z = V/I_drive, so it rides on a potential, and potentials are what the tree
# gauge moves. Solving this case on three different spanning trees moves L by
# 0.0035 nH and 0.0009 nH -- 0.018 % of itself, 7 % of the tolerance below.
# The LOCAL field does not get off so lightly: J and B within 2 mm of the cut
# move by 8.3 % and 7.4 %. No assertion in this file can see that, because they
# are all integrals. See LoopValidation.md section 7.1.
L_nH                   19.7854      0.05
