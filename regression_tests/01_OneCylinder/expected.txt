# Known-good physics for 01_OneCylinder, asserted by ../verify.py.
#
# THIS CASE IS A DIFFERENT REGIME FROM 02 AND 03, and that is why it is worth
# checking. Those have a/delta = 0.16 -- no skin effect, R = R_dc, Phi a clean
# z/L gradient. This one has a 10 mm radius at 50 Hz, so a/delta = 1.07: the
# current genuinely crowds outward, R rises above R_dc, and omega*L/R = 2.89
# means the case is inductive rather than resistive. Two of the checks that
# cases 02 and 03 use do not apply here, and verify.py skips a check whose key
# is absent -- see the notes on each below. An omitted key is a claim about the
# physics, not an exemption.
#
#   key                value        tol      what sets the tolerance
# ---------------------------------------------------------------------------
# Which input to run. Needed here because the folder holds four .aphi files
# -- 1 Hz, 50 Hz, a MUMPS variant and a 4-frequency sweep -- and without this
# check.bat would pick the sweep, which writes a different frequency into the
# same output dir. This names the DEFAULT-solver 50 Hz case deliberately, so
# check.bat exercises the internal solver rather than MUMPS.
input                  cylinder_50hz.aphi

# geometry, needed to compute the exact comparisons
a_mm                   10.0
length_mm              40.0
ngon                   36
sigma                  5.8e7
drive_voltage          1.0          1.0e-9
frequency              50.0

# R AGAINST KELVIN, NOT AGAINST R_dc. At a/delta = 1.07 the exact AC resistance
# is above the DC value, so `R_rel_error_max` -- which cases 02 and 03 use --
# is the wrong check and is deliberately absent: it would fail by the whole
# size of the skin effect, 2.6 %, and calling that an error would be backwards.
#
# The analytic value is Kelvin's, from the Kelvin functions ber and bei:
#
#     u = sqrt(2) a/delta = 1.513191
#     ber  =  0.918265305   bei  = 0.567230807
#     ber' = -0.215566682   bei' = 0.735963532
#     R_ac/R_dc = (u/2) (ber bei' - bei ber') / (ber'^2 + bei'^2) = 1.0267245
#
# computed from the defining series rather than by differencing J0 -- a central
# difference put bei' out in the 6th digit, which moved this reference in the
# 5th, and it is the number other numbers are judged against.
#
# We measure 1.026330 -- low by 0.038 %. The tolerance is that gap plus
# headroom. This is the only place in the suite where the skin effect itself is
# checked against theory; cases 02 and 03 cannot see it.
R_over_Rdc             1.0267245    0.001

# L has no closed form for a finite box, so it is pinned to catch CHANGE. Note
# it is 20.8 nH against case 02's 22.6 nH -- a different conductor radius, not
# a discrepancy.
L_nH                   20.8365      0.05

# PHI IS GAUGE DOMINATED HERE, so both Phi checks are deliberately absent.
#
# At omega*L/R = 2.89 the reactance dominates, and under the tree-cotree gauge
# Phi is not the z/L gradient -- it differs by -j*omega*psi, which is the
# larger term. Measured, Phi/V deviates from z/L by 0.49 and pointwise by 0.98,
# against 2e-3 and 1e-2 in case 02.
#
# THIS WAS TESTED, not assumed. Running the SAME mesh at 1 Hz instead of 50 Hz
# -- identical elements, only omega changed -- takes the deviation from 5.4e-01
# to 2.1e-03, a factor of 254. Discretisation error cannot do that; it would be
# about the same at both frequencies. So the deviation is the gauge, it scales
# with omega, and refining the mesh does not remove it: the refinement recorded
# below moved it only from 0.542 to 0.488 while halving the error in every
# gauge-INDEPENDENT quantity. Asserting a z/L gradient here would be asserting
# something false. R against Kelvin above and J below carry the load.
#
# (phi_vs_zL_worst_max and phi_pointwise_rel_max intentionally omitted.)

# THE J PROFILE, and why the reference is not the r=0 Bessel value. verify.py
# measures a mesh average over r < 0.25a divided by one over r > 0.90a. Where
# the profile is flat that is the same thing as J(0)/J(a); here it is not, so
# the reference is the Bessel function averaged over THE SAME RADII the mesh
# sampled. That reference therefore MOVES when the mesh changes, and it is
# 0.93993 for this mesh (it was 0.94089 before the core was refined).
#
#     Bessel at r=0 over r=a         0.926497   <- NOT the right comparison
#     Bessel at the sampled radii    0.93993    <- this one
#     measured                       0.94229    -- 0.250 % high
#
# The tolerance is that gap plus headroom.
J_ratio_exact          0.93993
J_ratio_tol            4.0e-3

# ---------------------------------------------------------------------------
# WHAT THE CORE REFINEMENT BOUGHT. cylinder.geo used to size the whole mesh from
# one UNSIGNED distance-to-lateral-surface field, which reads 10 mm on the axis
# -- the same as 10 mm out in the air -- so it coarsened INWARD and left the
# core at 4.4 mm elements with NO CELLS AT ALL inside r < 0.1a. It now caps the
# interior at lc_core = 2.0 mm with MathEval+Restrict+Min, and runs
# Mesh.OptimizeNetgen.
#
#                          before      after      exact      error
#   R/R_dc                1.025955   1.026330   1.0267245   0.075% -> 0.038%
#   <J>core/<J>surf       0.94544    0.94229    (own ref)   +0.483% -> +0.250%
#   axis-to-rim |J|         5.76 %     6.09 %      6.70 %    86% -> 91% captured
#   Phi/V vs z/L          5.42e-01   4.88e-01       --       gauge, barely moves
#   core cells, mid band   28/2658    130/3686
#   nodes                     4041       4755
#
# lc_core cannot usefully go below about 2 mm at N = 36: the polygon facet is
# 2a sin(pi/N) = 1.743 mm and a volume size well under the facet width makes
# slivers. A finer interior needs a larger N first.
# ---------------------------------------------------------------------------

# ---------------------------------------------------------------------------
# THE PHASE OF J, which is the other half of the Bessel solution.
#
# J_z is a PHASOR. The magnitude check above is the familiar skin-effect
# picture; arg(J_z) is independent of it and, in practice, the tighter test. An
# error in the -j*omega*A term of E = -j*omega*A - grad Phi shows up in the
# phase before it shows up in |J|, and until this check existed that half of the
# solution was never compared to anything.
#
# Measured as arg( <J>core / <J>surf ) over the SAME bands as the magnitude
# ratio, with the complex field averaged and the argument taken afterwards --
# averaging the arguments instead is wrong wherever the phase spread inside a
# band is not small, which is exactly the high-frequency case. Referring both to
# the surface band cancels the drive's own phase, and J = sigma E is gauge
# independent, so this number is physical rather than a convention.
#
# At a/delta = 1.07 the core lags the surface by 27.6 deg. We measure
# -27.42494 against the exact -27.55919, off by 0.134 deg -- 0.49 % of the lag,
# against 0.25 % on the magnitude.
phase_lag_exact       -27.55919     # degrees
phase_lag_tol           0.30
